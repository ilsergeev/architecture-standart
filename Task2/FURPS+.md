# FURPS+ Требования - MVP "Открытие депозитов онлайн"

| Код  | Требования                                                                                                   | Комментарий |
|------|--------------------------------------------------------------------------------------------------------------|-------------|
| **F**   | **Функциональные (Functionality)**                                                                        |             |
| F1   | Показ списка доступных депозитов с актуальными ставками на сайте                                              | Источник актуальных ставок требует определения (сейчас ставки ведутся вручную в XLS) |
| F2   | Подача заявки на депозит на сайте (телефон + ФИО)                                                             | Минимальный набор данных; новый клиент ещё не идентифицирован |
| F3   | Передача заявки (лида) в систему кол-центра для обратного звонка менеджера                                    | Требует интеграции сайта с системой кол-центра |
| F4   | Менеджер кол-центра может предложить особые условия по заявке                                                 | Связано с процессом согласования спецставок |
| F5   | Показ списка депозитов с актуальными ставками в интернет-банке                                                |             |
| F6   | Показ персонализированных ставок конкретному клиенту в интернет-банке                                         |             |
| F7   | Подача заявки на открытие депозита через интернет-банк (счёт + сумма)                                         | Заявка должна попасть к менеджеру бэк-офиса для обработки |
| F8   | Подтверждение операции СМС-кодом                                                                             | Верификация действия клиента |
| F9   | Ведение единого справочника ставок по депозитам                                                              | Сейчас ставки только в Excel |
| F10  | Менеджер бэк-офиса подтверждает условия депозита в АБС                                                        | АБС — точка финального создания/открытия депозита |
| F11  | СМС-уведомления клиенту: (1) после подтверждения ставки, (2) после открытия депозита                          | Информационные оповещения |
| **U**   | **Удобство использования (Usability)**                                                                     |             |
| U1   | Соблюдение принятой в компании системы дизайна (привычные цвета, брендированные элементы)                     | Должны использовать существующую дизайн-систему банка |
| **R**   | **Надёжность (Reliability)**                                                                               |             |
| R1   | Режим работы 24/7                                                                                            | Все сервисы депозитного контура |
| R2   | Доступность 99,9% для всех сервисов                                                                          | Допустимый простой примерно 9 часов в год |
| R3   | Отказоустойчивость на уровне ЦОД: при сбое основного ЦОД сервисы доступны на резервном и держат нагрузку      | Резервный ЦОД у банка уже есть — это средство, требование — сохранение доступности |
| R4   | Мониторинг доступности и латентности сервисов, алертинг о сбоях **(доп.)**                                    | Метрики нужны для реакции на возможные сбои и принятия решений о масштабировании |
| **P**   | **Производительность (Performance)**                                                                       |             |
| P1   | Отклик по всем операциям — миллисекунды                                                                      | Требование к скорости |
| P2   | Устранить медленную загрузку справочных данных при платежах (сейчас > 1 сек)                                  | Указывает на вынос справочных данных из АБС в отдельный сервис или использование кэша |
| P3   | Равномерное горизонтальное масштабирование и балансировка запросов между серверами, приложениями, ЦОД         | Относится к новым сервисам |
| **S**   | **Поддерживаемость (Supportability)**                                                                      |             |
| S1   | Разработка документации для дальнейшего расширения системы                                                    |             |
| S2   | Архитектура поддерживает интеграционное тестирование межсистемных сценариев **(доп.)**                        | Необходимо обеспечить возможность проводить интеграционное тестирование, так как появляется несколько новых сервисов |
| S3   | Модульность и расширяемость **(доп.)**                                                                        | Новый функционал это новые сервисы со стабильными контрактами, чтобы развивать систему без переработки существующего функцонала|
| **+R**  | **+ Ограничения (Restrictions)**                                                                           |             |
| +R1  | Шифрование трафика во всех клиентских каналах (сайт, интернет-банк)                                           | По сети передаётся чувствительная информация |
| +R2  | Обязательная очная идентификация нового клиента в отделении                                                   | Регуляторное требование; онлайн-подача не завершает открытие для нового клиента |
| +R3  | СМС-функционал дорабатывается силами IT-команды банка, вне ядра системы                                       | СМС-логика в ядре, обновление ядра завязано на подрядчика — доработку ядра избегаем |
| +R4  | Сегментированный доступ к справочнику ставок: кредиты ведут показатели риска, депозиты — ставки; чужой сегмент закрыт | Требование безопасности из текущего процесса |
| +R5  | Приоритет технологий, уже используемых в банке                                                                | Переиспользуем то, в чём есть экспертиза и сопровождение |
| +R6  | Новые технологии допустимы только при совместимости с существующими платформами и наличии экспертизы внутри банка | Экспертиза — хотя бы на уровне языка программирования |
| +R7  | Для очередей сообщений использовать Kafka                                                                     | По требованию бизнеса |
| +R8  | Новый функционал строится вне ядра ИБ                                                                         | .NET Framework 4.5 несовместим с Kafka и горизонтальным масштабированием; обновление ядра завязано на подрядчика |
| +R9 | Не размещать нагрузочно-критичные данные (справочник ставок) в АБС                                            | Oracle АБС перегружен, масштабируется только вертикально, логика в PL-SQL |
| +R10 | В MVP обработка заявки остаётся ручной (менеджер бэк-офиса по существующему процессу)                         | Автоматизация согласования — вне скоупа MVP |
| +R11 | ИБ не работает с API/БД АБС напрямую в новом процессе — только через промежуточный слой                       | БД АБС перегружена; прямой доступ несовместим с требованием 99,9% |
| +R12 | АБС масштабируется только вертикально (ограничение Oracle-БД)                                                 | Горизонтальный масштабируемый слой строится в обход АБС |
